# Benchmarks

Generated by `npm run benchmark`, which builds the workbench, opens the
benchmark page in every browser this machine can produce, and records what
each one reported. Nothing here is written by hand.

The ceilings are deliberately generous — an order of magnitude above what an
operation costs today rather than a factor of two. A suite that failed on a
loaded laptop would be switched off within a week, and a suite nobody runs
measures nothing. What these catch is the change that makes an operation cost
a hundred times what it did.

## Browsers with no measurement

Named rather than omitted: a matrix that reported only what it managed to
run would get quieter every time something broke.

- **safari** — Safari was not found on this machine. Not obtainable here. Safari does not run on Linux, and another WebKit reported under its name would be a different measurement wearing the same label.

## Areas with no measurement

- **Emulator input, frames and audio** — Every emulator measurement needs a booted machine, which needs firmware, and no firmware may enter this repository or the built image. These are measured with the conformance suite, where firmware has been supplied.
- **Debugger acknowledgement** — A debugger acknowledgement is a round trip to a running machine, so it has the same firmware dependency as the emulator itself.

## Why each case matters

- **The workbench renders its first frame** — This is the whole wait between opening the product and being able to do anything with it, so it is the one measurement everybody experiences.
- **A keystroke is applied to a two-thousand-line source** — Edit latency is the only measurement a person feels continuously. A regression here does not slow a task down, it makes typing unpleasant, which is a different and worse kind of failure.
- **Diagnostics are recomputed for a two-thousand-line source** — Diagnostics run after every pause in typing. If they cost more than the pause, they run behind the source and report on a program nobody has any more.
- **A two-thousand-line source is assembled** — The build is the loop everything else waits on: run, debug and test all begin with it, so its cost is paid several times for every change.
- **Fifty thousand trace events are filtered** — A trace is taken when something is already wrong, and a filter that cannot keep up with the window turns the one tool for a hard bug into a thing that hangs.
- **A sixty-four by sixty-four tile map is drawn** — An asset canvas redraws on every stroke, so its cost is the difference between drawing and waiting.
